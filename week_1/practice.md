# Неделя 1. Самостоятельная практика: среда и первый цикл «порождение → проверка»

Курс «ИИ-ассистенты для исследователя. AI4Science».

**Результат недели:** на вашем ноутбуке работает учебный агент, ваш
исследовательский проект лежит в git-репозитории, и в журнале проекта есть
первая запись о задаче, которую выполнил агент, с явной точкой проверки.

**Время:** около 3 часов.

Все шаги выполняются на своём материале: статья, данные, расчёт или заметки
по вашей теме. Если своего материала пока нет, используйте учебный пример
`example_boyle/` из этой папки: скопируйте его папку `project/` и работайте в копии.

---

## Шаг 0. Проверка окружения (15 мин)

В терминале (Windows — PowerShell, macOS и Linux — терминал):

```bash
git --version
python --version        # macOS / Linux: python3 --version
```

**Должно получиться:** git любой свежей версии, Python 3.10 или новее.

Если чего-то нет:
- Windows: Python — <https://www.python.org/downloads/windows/> (при установке
  отметить «Add python.exe to PATH») или `winget install -e --id Python.Python.3.12`;
  git — <https://git-scm.com/download/win> или `winget install -e --id Git.Git`.
- macOS: `xcode-select --install` (git), Python — <https://www.python.org/downloads/macos/>
  или Homebrew.
- Ubuntu: `sudo apt-get install -y git python3 python3-venv`.

После установки откройте новый терминал.

## Шаг 1. Установка агента (30 мин)

Агент ставится в отдельную папку, не в папку вашего проекта.

**Windows 10/11:**

```powershell
git clone https://github.com/andkhalov/AI4Science.git
cd AI4Science
setup.bat
```

**macOS и Linux:**

```bash
git clone https://github.com/andkhalov/AI4Science.git && cd AI4Science && ./setup.sh
```

Мастер установки спросит ключ Yandex AI Studio (`YANDEX_CLOUD_API_KEY`) и
идентификатор каталога (`YANDEX_CLOUD_FOLDER`); оба выдаются на курсе.
Ключ записывается в файл `.env` в папке агента. Этот файл нельзя публиковать
и добавлять в git.

Откройте новый терминал и выполните:

```bash
ai4science doctor
```

**Должно получиться:** строки `goose: 1.50.0`, `MCP ai4science: OK (17 инструментов …)`,
`lean-checker: подключён`.

Модели и их короткие имена выводит `ai4science models`. Модель на всю сессию
задаётся при запуске: `ai4science -m qwen235`. Внутри сессии модель меняется
командой `/model qwen235`; история сессии при этом сохраняется. Все команды
сессии — `/help`, текущее состояние (модель, режим, расход токенов) — `/status`.

Если установка в Windows не завершилась, `setup.bat` покажет запасной путь
через WSL2. Подробности и частые ошибки — в README репозитория агента.

## Шаг 2. Репозиторий проекта (30 мин)

Настройте git один раз на компьютере:

```bash
git config --global user.name "Имя Фамилия"
git config --global user.email "you@example.org"
```

Скопируйте папку `project_template/` в место, где будет жить ваш проект, и
переименуйте её. Внутри:

```
my_project/
  AGENT.md       договор с агентом: цель, данные, соглашения, запреты
  diary.md       журнал проекта (записи только добавляются)
  data/          исходные данные (агент их не изменяет)
  src/           код
  memory/        заметки и сводки для агента
  paper/         текст статьи
  .gitignore
```

Заполните в `AGENT.md` разделы «Цель проекта» и «Данные» — по 2–4 предложения.
Положите в `data/` или `paper/` материал, с которым будете работать.

```bash
cd my_project
git init
git add -A
git commit -m "Начало проекта: AGENT.md и материалы"
```

**Должно получиться:** `git log --oneline` показывает один коммит.

Репозиторий можно держать только локально или на любой платформе
(GitHub, GitLab, GitVerse и другие).

## Шаг 3. Режим доступа и рабочая папка (10 мин)

Агент выполняет команды в той папке, из которой запущен. Запускайте его
только из папки проекта, не из домашней папки и не из папки с чужими данными.

| Режим | Когда использовать |
|---|---|
| `ai4science --mode approve` | незнакомая задача, первые запуски: каждое действие подтверждается |
| `ai4science` (`smart_approve`) | обычная работа: чтение без подтверждения, запись и команды — с подтверждением |
| `ai4science run "…"` (`auto`) | короткие задачи, результат которых вы проверите |
| `ai4science --mode chat` | обсуждение без действий |

Режим меняется и внутри сессии: `/mode approve`.

Перед первой задачей сделайте коммит: всё, что изменит агент, будет видно в
`git diff` и при необходимости откатывается.

## Шаг 4. Первый цикл «порождение → проверка» (60 мин)

1. Сформулируйте небольшую задачу по своему материалу, результат которой
   можно проверить независимо от агента. Примеры — ниже.
2. Запустите агента из папки проекта в режиме `approve` и дайте задачу.
   Попросите записать в `diary.md` итог и способ проверки.
3. **Точка проверки.** Проверьте результат сами, не спрашивая агента:
   запустите полученный код, пересчитайте значение другим способом,
   сверьте утверждение с источником, откройте файл и прочитайте его.
4. Добавьте в `diary.md` запись по форме:

```markdown
## 2026-09-20 — <короткое название задачи>
- Запрос агенту: <текст запроса>
- Что сделал агент: <файлы, команды>
- Результат: <что получено>
- Точка проверки: <чем проверяли, независимо от агента>
- Итог проверки: принято / отклонено / принято с исправлением — <почему>
```

5. Посмотрите изменения и сделайте коммит:

```bash
git status
git diff
git add -A
git commit -m "Первый цикл: <задача>"
```

### Примеры задач по дисциплинам

| Дисциплина | Задача агенту | Точка проверки |
|---|---|---|
| Физика | по таблице измерений оценить постоянную величину и её разброс | пересчёт одной-двух строк вручную или отдельным скриптом |
| Химия | рассчитать молярные массы веществ из списка формул | сверка двух-трёх значений со справочником |
| Биология | посчитать долю GC в последовательностях FASTA | независимый расчёт на одной короткой последовательности |
| Науки о Земле | перевести координаты станций из градусов-минут в десятичные градусы | обратный перевод одной точки, проверка на карте |
| Математика | численно проверить неравенство на сетке значений | вычисление в нескольких граничных точках вручную |
| Любая | составить сводку статьи в пять утверждений | каждое утверждение найдено в тексте статьи, указана страница |

Учебный пример `example_boyle/`: папка `project/` с данными изотермического
процесса и рядом с ней независимая проверка `check_boyle.py`. Скопируйте
`project/` в отдельную папку и запускайте агента там; скрипт проверки остаётся
вне проекта, чтобы агент его не видел. В данных есть одна ошибка: получите
вывод агента и сравните его с результатом
`python check_boyle.py <копия>/data/measurements.csv`.

## Если агента нужно удалить

Установка затрагивает три места: папку агента, команду `ai4science` и файл
счётчика токенов в домашней папке. Команды удаления для macOS, Linux и Windows
— в разделе «Удаление» файла README репозитория агента. Проекты, в которых
работал агент, лежат в своих папках и при удалении не затрагиваются.

## Артефакт недели 1

- **Что сделать:** среда на своём ноутбуке в git-репозитории и цикл
  «порождение → проверка» с явной точкой проверки.
- **Минимум для «зачтено»:** `ai4science doctor` без ошибок; проект в
  git-репозитории с `AGENT.md` и `diary.md`; режим доступа выбран осознанно;
  в `diary.md` есть запись с заполненной точкой проверки и итогом.
- **Идёт в:** домашнюю работу 1 «Среда и контекст» (объявляется на неделе 1,
  постановка выдаётся на неделе 2, сдача — к неделе 6).
- **Время:** около 3 часов.
- **Стартовый набор:** `project_template/`, учебный пример `example_boyle/`.
- **Где лежит у вас:** папка проекта под git.
- **Самопроверка:**
  1. `ai4science doctor` завершается без строк `FAIL`.
  2. `git log --oneline` в папке проекта показывает не меньше двух коммитов.
  3. `git check-ignore .env` в папке агента печатает `.env`.
  4. В `diary.md` у записи заполнены поля «Точка проверки» и «Итог проверки».
  5. Точку проверки можно повторить без агента.
- **Типовые ошибки:** см. ниже; список дополняется после разбора на неделе 2.

## Типовые ошибки

| Симптом | Причина | Что сделать |
|---|---|---|
| Windows: `python` открывает Microsoft Store | заглушка вместо установленного Python | установить Python с python.org с «Add to PATH» или использовать `py -3` |
| `ai4science` не найдена после установки | терминал открыт до изменения PATH | открыть новый терминал; на Windows запуск `bin\ai4science.bat` из папки агента |
| `MCP ai4science: FAIL` | не установились зависимости | удалить папки `.venv` и `.tools` в папке агента и запустить установщик заново |
| после `/model` запрос завершается ошибкой | опечатка в имени модели или модель временно недоступна | `ai4science models` — список имён; вернуться к модели по умолчанию: `/model qwen` |
| агент изменил файлы не в той папке | запуск не из папки проекта | запускать из папки проекта; вернуть изменения через `git restore` |
| ключ оказался в репозитории | `.env` добавлен в git | удалить файл из истории, запросить новый ключ, проверить `.gitignore` |
