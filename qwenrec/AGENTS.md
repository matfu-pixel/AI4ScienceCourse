# AGENTS.md — QwenRec

Этот проект является подпроектом будущего проекта про фундаментальную модель
для рекомендательных систем. Цель проекта показать, что инициализация рекомендательного
трансформера весами предобученной LLM (Qwen3-0.6B-Base) улучшает качество на задаче
Next Item Prediction против случайной инициализации.

## 0. Цель и образ результата

Текущая задача — подготовить данные для Next Item Prediction из `data/listens.parquet`.

В конце в проекте существуют:
- `src/prepare_data.py` — скрипт; запускается командой `.venv/bin/python src/prepare_data.py`
  и создаёт оба файла ниже;
- `results/vocab.parquet` — словарь: топ-500000 треков по числу прослушиваний.
  Столбцы `item_id, token, n_listens`. Порядок: по убыванию `n_listens`, при равенстве —
  по возрастанию `item_id`; `token` — номер строки в этом порядке, 0..499999;
- `results/sequences.parquet` — одна строка на пользователя, у которого есть хотя бы одно
  прослушивание трека из словаря. Столбцы `uid, train_tokens, test_tokens` (списки токенов).
  Прослушивания треков вне словаря отбрасываются. Порядок внутри списков — по `timestamp`,
  при равных `timestamp` — как в `listens.parquet`. Тест — прослушивания с
  `timestamp >= max(timestamp) - 86400` (последние сутки), остальные — train.
  Если у пользователя нет событий в одной из частей, список пустой.

Ничего больше создавать не надо.

## 1. Критерий готовности

Работа считается выполненной, когда проходит проверка:

```
.venv/bin/python checks/check.py
```

Код 0 — принято. Проверка сама пересчитывает эталон из `data/listens.parquet`.
Вызови её сам перед тем, как дать окончательный ответ. Ответ без пройденной
проверки не принимается.

### Чего агент не может знать сам

- `timestamp` в `data/listens.parquet` — секунды от начала датасета с шагом 5 с
  (0…26 000 000, около 301 дня), а не Unix-время: в календарные даты не переводится.
- В `listens.parquet` есть и недослушанные треки: `played_ratio_pct` < 50 у 37 % строк,
  > 100 (перемотка) у 0,5 %; в задачах проекта прослушивания по нему не фильтруются.
- У 25 616 из 500 000 треков словаря нет контентного эмбеддинга в
  `data/embeddings_listens.parquet`: для semantic ids им нужен запасной вариант.
- Предварительные результаты в `paper/tg_posts.md` получены на Yambda-5b и Qwen-9B,
  а проект работает с Yambda 50m: числа оттуда с нашими напрямую не сравнивать.

## 3. Инструменты и границы

- Python 3.13 из `.venv` (numpy, pandas, pyarrow); запускать из корня проекта как
  `.venv/bin/python …`. Новые пакеты — только `.venv/bin/python -m pip install …`.
- `data/embeddings.parquet` — 13,8 ГБ: целиком в память не читать, только нужные
  столбцы и строки через pyarrow. `listens.parquet` в память помещается.
- Сеть и Lean не нужны: `AI4SCIENCE_WEB_DISABLED=1 ai4science --no-lean`.

## 5. Протокол и режим работы

Режим — ReAct: прочитать данные, написать скрипт, запустить, посмотреть результат.
- Сначала отладь скрипт на первых ~1 млн строк, затем запусти на всех данных.
- После полного запуска — проверка. Если она не прошла: прочитай сообщение, исправь
  скрипт, перезапусти его и проверку.
- Код — в `src/`, запускать перед тем, как сообщать результат.
