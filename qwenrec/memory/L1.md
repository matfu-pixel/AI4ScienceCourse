## PLUM: адаптация предобученных языковых моделей для рекомендательных систем (с. 1–2)

Авторы предлагают PLUM — фреймворк для адаптации предобученных больших языковых моделей (LLM) к задачам рекомендательных систем промышленного масштаба. Метод состоит из трёх этапов: токенизация предметов с помощью Семантических ID (Semantic IDs, SIDs) на базе SID-v2; дообучение (continued pre-training, CPT) на смеси предметных данных, пользовательских последовательностей и общего текста; тонкая настройка для генеративного поиска, где декодер-модель авторегрессионно генерирует SIDs рекомендуемых предметов. Эксперименты на внутренних видео-данных YouTube показывают существенное улучшение качества извлечения по сравнению с производственной моделью на больших embedding-таблицах. При этом PLUM использует Transformer с 100× плотными параметрами больше, но общая стоимость обучения сопоставима благодаря более быстрой сходимости. Наблюдается эффективное масштабирование: качество растёт вплоть до Mixture-of-Experts (MoE) модели с более чем 900M активированных параметров (около 4.2B параметров в целом). Фреймворк развёрнут в продакшене YouTube.
## Semantic IDs и Continued Pre-training (с. 3–4)

Метод PLUM формирует семантические идентификаторы (SID) через RQ-VAE с мульти-модальным слиянием эмбеддингов (с. 3), многоуровневыми кодовыми словарями кардинальности 2048/2^(level-1) (с. 3) и прогрессивным маскированием (с. 3). Контрастная потеря по со-встречаемости L_con = −Σ exp(sim(p_i, p_i+)) / Σ exp(sim(p_i, p_j)) (с. 3) привязывает SID к поведению пользователей, формируя семантические кластеры из совместных просмотров (с. 3). Итоговая функция потерь квантователя L = L_recon + L_rq + L_con (с. 4). Продолженное предобучение (CPT) обеспечивает семантическую привязку SID к текстовым токенам базовой языковой модели (с. 4); стадия CPT — 1 млн шагов с размером батча 16, около 260 млрд токенов, смесь пользовательских данных и метаданных видео по 50% (с. 4). Модель сохраняет способность к few-shot обучению и генерации свободного текста (с. 4).
## Generative Recommendation с использованием PLUM (с. 5–6)

Авторы сравнивают генеративный подход к рекомендациям PLUM на базе 900M MoE-модели семейства Gemini-1.5 с продакшен-моделью Large Embedding Model (LEM): по метрикам реакции пользователей качество сопоставимое («competitive»), WT/View на LFV — 0,72× (с. 5). Метод: двухэтапное обучение — continued pre-training (CPT) и fine-tuning на SID-токенах с beam search. Результаты: эффективный размер словаря в 2,60× (LFV) и 13,24× (Shorts) выше LEM (с. 5); CTR на 1,42× (LFV) и 1,33× (Shorts) (с. 5). В онлайн-экспериментах добавление PLUM дало +0,76% CTR для LFV и +4,96% для Shorts (с. 6). Абляция 2×2 на MoE-900M, Recall@10 на 8-й день (с. 6, табл. 5): R1 (случайная инициализация, без CPT) 0,19; R2 (LLM, без CPT) 0,23; CR1 (случайная + CPT) 0,27; CR2 (LLM + CPT) 0,28. Уникальность SIDv2 достигает 96,7% против 94,0% у SIDv1 (с. 6). PLUM-модели крайне sample-efficient: 900M MoE обучается на ~250M примеров в день против нескольких миллиардов у LEM (с. 6).
## Масштабирование генеративного поиска (с. 7–9)

Авторы исследуют масштабирование генеративной рекомендательной системы PLUM на четырёх моделях Gemini-1.5 MoE: MoE-110M, MoE-370M, MoE-900M и MoE-3B (с. 7). Эксперименты проведены на производственных данных YouTube с длиной входной последовательности 1,536 токенов на 1,024 Google's v6e TPUs (с. 7). Выявлена степенная зависимость между Iso-FLOPS и training/evaluation loss для всех размеров моделей (с. 8). Оценка Recall@10 продолжает расти с увеличением вычислений, не демонстрируя признаков переобучения: MoE-110M обучался 4.24 эпохи без деградации (с. 8). Модель MoE-3B обработала лишь 0.57 эпохи из-за меньшего batch size (с. 8). Вывод: compute-optimal training требует синхронного масштабирования объёма данных и размера модели (с. 8).
## Приложение: пилотное исследование масштабирования и in-context обучение (с. 10–11)

**Главное утверждение.** Процесс обучения толерантен к выбору скорости обучения в разумном диапазоне, однако для вычислительно оптимального обучения необходимо максимизировать размер батча до предела аппаратной памяти (с. 10).

**Метод.** Пилотное исследование на модели MoE-900M: 4 тренера по 256 TPU каждый, инициализация из одного предобученного чекпоинта. Систематически варьировались скорость обучения (от 5×10⁻⁵ до 2×10⁻⁴) и размер батча (от 0.5× до полного насыщения HBM). Тестирование длилось около двух недель (с. 10).

**Результат.** Разница между скоростью 1×10⁻⁴ и 5×10⁻⁵ статистически незначима; удвоение до 2×10⁻⁴ дало существенно худший результат (с. 10). Уменьшение батча вдвое требует более чем двукратного увеличения шагов обучения для сопоставимого качества (с. 10). Модель с инициализацией от предобученной LLM способна к few-shot in-context обучению с семантически осмысленными завершениями, тогда как модель со случайной инициализацией не формирует связных фраз (с. 10; примеры — табл. 8, с. 11).
